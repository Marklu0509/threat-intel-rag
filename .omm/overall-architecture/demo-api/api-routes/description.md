GET /health returns status, model, ATT&CK version and the deployed git SHA; ?check=llm pings the provider (cached 60 s, reports error types only, never messages). POST /ask validates length (1–300 chars), applies the rate limiter using the last X-Forwarded-For entry (the one Azure's ingress appended), runs answer_question through a recording retriever, and returns claims, refusal info, revoked-ID substitutions and the retrieval trace. Errors map to 400 / 429 (with Retry-After) / 503 daily limit / 502 upstream. Logs the question, outcome and latency as JSON, never the IP (Q50).
